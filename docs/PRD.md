# MindMeal（有意食）MVP 產品需求文件

**版本：** MVP v1.0  
**文件狀態：** 可供產品設計與前端開發使用  
**產品標語：** Eat with Intention.

## 1. 產品願景

MindMeal 是一款以 AI 為核心的飲食導航 App。它不要求使用者繁瑣記錄或只檢討熱量，而是回答一個更實際的問題：

> 今天還差什麼，下一餐可以怎麼吃？

系統根據個人目標、當日飲食與營養缺口，提供溫和、具體、可立即行動的下一餐建議。

## 2. MVP 目標

讓新使用者在 3–5 分鐘內完成：

1. 建立個人飲食目標。
2. 記錄並分析第一餐。
3. 確認或修正 AI 判讀。
4. 看見今日營養進度更新。
5. 取得下一餐方向、附近選擇或採買清單。

本版主要用於高擬真展示與使用者測試，不以醫療診斷、精準營養處方或正式第三方服務串接為目標。

## 3. 目標使用者

- 20–35 歲、以外食為主。
- 有健康、減脂、增肌或均衡飲食需求。
- 不熟悉營養計算，不知道下一餐如何選擇。
- 不喜歡逐項輸入食材或長時間記錄。
- 希望得到低壓、沒有責備感的提示。

## 4. 核心價值與設計假設

**核心價值：** 不是紀錄飲食，而是導航飲食。

待驗證假設：

- 使用者能理解「今日還差多少」比理解大量歷史數據更容易。
- 拍照後只做少量修正，能降低記錄摩擦。
- 具體食物與店家建議，比單純顯示營養缺口更可行動。
- 無責備語氣能提高完成記錄與持續使用意願。

## 5. MVP 範圍

### 5.1 個人目標設定

初次使用需收集：

- 年齡、性別、身高、體重。
- 每週運動天數／活動量。
- 飲食目標：減脂、維持、增肌、均衡飲食。
- 飲食偏好：素食、少辣、不吃牛、低糖等，可複選。
- 日常外食情境：便利商店、便當、餐廳、自煮，可複選。
- 定位權限（選填），並清楚說明用途。

每個步驟只問一組相關問題，搭配簡短趣味回應降低填寫疲勞。完成後顯示示範性的每日熱量、蛋白質、水分與蔬菜目標。

### 5.2 餐點記錄與 AI 分析

記錄入口包含：

- 拍照（核心測試路徑）。
- 相簿、搜尋、語音、掃碼、常吃餐（可作為可點擊入口或模擬狀態）。

分析結果包含：

- 餐點類型、主要食材。
- 預估熱量、蛋白質、碳水、脂肪。
- 蔬菜、精緻澱粉、含糖飲料與油炸食物情況。

使用者可快速修正：

- 食材與配料。
- 是否吃完。
- 飯量：半碗、一碗、加飯。
- 醬料：少、正常、多。

### 5.3 今日飲食儀表板

首頁需在 3 秒內回答「今天還差什麼」，顯示：

- 今日剩餘／已攝取熱量與建議範圍。
- 蛋白質、碳水、脂肪與水分進度。
- 運動量與消耗熱量的示意資料。
- 已完成餐次。
- 當日飲食平衡分數。
- AI 人體／身體需求視覺提示。
- 一句今日方向提示與主要記錄 CTA。

儲存餐點後，數值、完成餐次、平衡分數及下一餐建議需同步更新。

### 5.4 下一餐飲食導航

根據當日營養缺口提供：

- 缺口摘要，例如「蛋白質還差約 25g」。
- 下一餐搭配方向與具體食物。
- 附近餐廳／便利商店推薦卡及地圖示意。
- 根據缺口產生的超商或超市採買清單。

### 5.5 趨勢與個人設定

趨勢頁以少量卡片呈現：

- 本週熱量、蛋白質、飲水、體重與平衡分數。

個人頁包含：

- 每日目標、健康資料、飲食偏好。
- 通知、定位與帳號設定。

## 6. 資訊架構

```text
Splash
└── Welcome（登入／註冊／訪客開始）
    └── Onboarding
        ├── 基本資料
        ├── 飲食目標與活動量
        ├── 飲食偏好
        ├── 外食情境
        └── 每日建議結果／定位詢問

App Shell
├── Home／今日飲食儀表板
├── Trend／趨勢
├── Scan／記錄
│   ├── 拍照／相簿／搜尋／語音／掃碼／常吃餐
│   ├── AI 辨識
│   ├── 餐點分析與調整
│   └── 儲存完成
├── Nearby／下一餐導航
│   ├── 推薦與地圖
│   └── 採買清單
└── Profile／個人設定
```

底部導覽順序為 Home、Trend、中央 Scan、Nearby、Profile。

## 7. 核心 User Flow

### 7.1 新使用者

```text
Splash → Welcome → 基本資料 → 目標與偏好 → 每日建議／定位詢問
→ Dashboard → 拍照第一餐 → AI 辨識 → 修正 → 儲存
→ Dashboard 更新 → 下一餐推薦
```

### 7.2 日常使用

```text
Dashboard → 拍照或手動記錄 → AI 分析 → 快速確認／修正
→ 儲存 → 今日進度更新 → 下一餐推薦 → 附近店家或採買清單
```

### 7.3 例外與返回

- 使用者可略過登入，以訪客身分體驗。
- 拒絕定位後仍可使用全部核心功能，Nearby 顯示示範地點或手動選區提示。
- AI 判讀錯誤時，使用者可編輯食物、份量與醬料後再儲存。
- 未完成餐點時可返回，不得誤更新 Dashboard。
- 空白狀態需引導記錄第一餐，不顯示錯誤或責備訊息。

## 8. 頁面需求與驗收重點

| 頁面 | 主要內容 | 主要動作 | 驗收重點 |
|---|---|---|---|
| Splash／Welcome | 品牌、價值主張 | 開始、登入、略過 | 可進入設定；視覺簡潔 |
| Onboarding | 五步驟設定 | 上一步、下一步、完成 | 有進度、基本驗證、選擇會保留 |
| 每日建議 | 熱量與營養方向 | 開始記錄第一餐 | 可進入 Dashboard／Scan |
| Home | 今日缺口、進度、AI Insight、餐次 | 開始記錄、看下一餐 | 儲存餐點後內容更新 |
| Scan | 相機框與多種入口 | 拍攝／選擇 | 可進入分析模擬流程 |
| AI Analysis | 食物、營養、修正控制 | 儲存這餐 | 修正會影響顯示數值 |
| Save Success | 完成回饋與新方向 | 回到今天、找附近吃什麼 | 兩條路徑皆可完成 |
| Next Meal／Nearby | 缺口、推薦卡、地圖、清單 | 導航、勾選清單 | 無定位時有安全降級 |
| Trend | 四至五張趨勢卡 | 切換期間 | 不需複雜分析功能 |
| Profile | 目標、偏好、通知、定位 | 編輯／切換 | 可見可操作狀態 |

## 9. 內容與 AI 語氣

原則：簡短、友善、具體、無責備、不做醫療診斷。

- 不建議：「你今天熱量超標了。」
- 建議：「今天油脂已經較充足，晚餐選清爽蛋白質與蔬菜會更平衡。」
- 不建議：「減重失敗。」
- 建議：「今天是彈性的一餐，明天回到原本節奏就很好。」
- 空白狀態：「今天還沒有紀錄。拍下第一餐，AI 幫你開始分析。」

營養數值在原型中應標示為估算或示範，不宣稱醫療準確性。

## 10. 原型資料與技術邊界

MVP 可使用本機假資料完成測試：

- AI 辨識以固定延遲與預設分析結果模擬。
- 相機可使用檔案上傳或示範圖片，不需雲端 Vision API。
- 地圖使用靜態／示意地圖與假店家卡，不需 Google Maps API。
- 語音、條碼、登入、通知與定位可為入口及狀態模擬。
- 使用 localStorage 保存 onboarding、餐點與 Dashboard 狀態。
- 必須可離線開啟；首版採 HTML、CSS、JavaScript，無框架與建置步驟。

## 11. 成功指標

使用者測試追蹤：

- 完成個人目標設定率。
- 完成第一餐記錄率。
- AI 結果修正率與完成時間。
- 儲存後是否能說出「今天還差什麼」。
- 是否查看下一餐推薦。
- 是否成功選擇店家或加入採買清單。
- 核心流程總完成時間與主觀操作負擔。

## 12. 非目標與後續版本

本版不包含正式醫療建議、真實營養資料庫、付款、社群或後端帳號系統。後續可評估 Apple Health／HealthKit、Garmin、Google Fit、Vision、條碼、餐廳與營養 API、正式地圖服務、Vue 3 與 Supabase。
