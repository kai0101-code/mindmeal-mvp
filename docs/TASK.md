# MindMeal（有意食）MVP 開發任務清單

本文件供開發工作區直接執行。需求優先級：P0 為核心測試流程，P1 為完整展示，P2 為後續加值。

## 0. 完成定義

交付物是一個可離線開啟、手機優先、可點擊的高擬真原型。使用者必須能從 Welcome 完成 onboarding、記錄一餐、修正 AI 結果、看見 Dashboard 更新，再前往下一餐建議。所有核心路徑無死連結、無阻斷錯誤。

## 1. 技術基線

- 首版使用 HTML、CSS、原生 JavaScript，無框架、無建置步驟、無外部 CDN。
- 入口檔為 `index.html`；可視需要拆成 `styles.css`、`app.js` 與本機 assets。
- 使用 localStorage 保存 onboarding、今日餐點與購物清單。
- AI、相機、地圖、語音、條碼、登入與定位皆可模擬，但 UI 必須誠實反映為示範。
- 遵循 `PRD.md` 與 `DESIGN.md`；若衝突，先滿足核心 User Flow 與可用性。

## 2. 里程碑與任務

### Milestone A — 專案骨架與設計系統

- [ ] **T01 / P0：建立離線專案骨架**
  - 建立頁面容器、路由／畫面狀態與本機資源。
  - 驗收：直接開啟 `index.html` 即可使用；無網路請求失敗。

- [ ] **T02 / P0：建立 Design Tokens 與共用元件**
  - 色彩、字級、間距、圓角、陰影、按鈕、卡片、chip、progress bar。
  - 驗收：核心元件外觀一致，互動狀態完整。

- [ ] **T03 / P0：建立全域狀態與假資料**
  - 使用者設定、營養目標、餐點、推薦店家、購物清單。
  - 驗收：重新整理後保留進度；提供重設 Demo 的方式。

### Milestone B — 首次使用流程

- [ ] **T04 / P0：Splash 與 Welcome**
  - 品牌、標語、開始／訪客入口與微量波浪動畫。
  - 驗收：3 秒內可找到開始按鈕；可進 onboarding。

- [ ] **T05 / P0：Onboarding 基本資料**
  - 年齡、性別、身高、體重及基本輸入驗證。
  - 驗收：無效值不可前進，錯誤訊息清楚且不清空資料。

- [ ] **T06 / P0：目標、運動量與飲食偏好**
  - 目標單選、運動量、偏好多選。
  - 驗收：返回再前進時選擇仍保留。

- [ ] **T07 / P0：外食情境、趣味回應與定位選項**
  - 外食情境多選；定位可允許或略過。
  - 驗收：拒絕定位不阻擋流程，趣味文字不干擾操作。

- [ ] **T08 / P0：每日建議結果**
  - 顯示示範熱量、蛋白質、水分與蔬菜目標。
  - 驗收：數值標示為建議／估算；CTA 可進 Dashboard 或第一餐記錄。

### Milestone C — Dashboard

- [ ] **T09 / P0：建立 Dashboard 首屏**
  - 今日剩餘熱量、記錄 CTA、連續天數。
  - 驗收：手機首屏清楚看見核心數字與 CTA。

- [ ] **T10 / P0：營養進度與 AI 人體**
  - 蛋白質、碳水、脂肪、水分進度，以及文字輔助的人體需求視覺。
  - 驗收：數值與視覺一致；不只靠顏色傳達狀態。

- [ ] **T11 / P0：AI Insight、餐次與平衡分數**
  - 顯示一句今日方向、已完成餐次、下一餐預覽。
  - 驗收：空白與已有紀錄兩種狀態皆完整。

- [ ] **T12 / P0：Bottom Navigation**
  - Home、Trend、Scan、Nearby、Profile，Scan 置中。
  - 驗收：目前位置清楚、可單手操作、切換不遺失資料。

### Milestone D — 餐點記錄核心流程

- [ ] **T13 / P0：Scan 記錄入口**
  - 拍照為主，相簿、搜尋、語音、掃碼、常吃餐為次。
  - 驗收：每個入口有回饋；未實作功能不形成死路。

- [ ] **T14 / P0：模擬拍攝與 AI 掃描**
  - 示範圖片／檔案選擇、掃描線、分析中狀態。
  - 驗收：載入後穩定進入固定分析結果；可取消／重試。

- [ ] **T15 / P0：餐點分析結果**
  - 食材、熱量、蛋白質、碳水、脂肪與飲食類型標示。
  - 驗收：內容可讀，所有數值標示為估算。

- [ ] **T16 / P0：餐點快速修正**
  - 飯量、醬料、配料、是否吃完。
  - 驗收：選擇立即反映在摘要或估算數值；可返回不儲存。

- [ ] **T17 / P0：儲存與 Dashboard 更新**
  - 寫入餐點，更新熱量、營養進度、餐次、分數與 Insight。
  - 驗收：同一筆不可重複加入；重新整理後資料仍存在。

- [ ] **T18 / P0：成功頁與分流**
  - 提供「回到今天」及「找附近吃什麼」。
  - 驗收：兩條路徑皆正確，返回後不重複儲存。

### Milestone E — 下一餐導航

- [ ] **T19 / P0：營養缺口與下一餐方向**
  - 根據目前假資料計算／選擇具體建議。
  - 驗收：建議和 Dashboard 顯示的缺口一致，語氣無責備。

- [ ] **T20 / P1：店家卡與地圖示意**
  - Subway、健康便當、便利商店等假店家與距離、適配理由。
  - 驗收：標示為示範資料；無定位時仍可使用。

- [ ] **T21 / P1：採買清單**
  - 依缺口建立雞胸、豆腐、茶葉蛋、牛奶、地瓜等項目。
  - 驗收：可勾選、狀態持久化並可清除已完成項目。

### Milestone F — 次要頁面

- [ ] **T22 / P1：Trend**
  - 熱量、蛋白質、飲水、體重、平衡分數卡。
  - 驗收：使用少量可理解圖表；示範資料標示清楚。

- [ ] **T23 / P1：Profile**
  - 每日目標、健康資料、偏好、通知、定位、帳號。
  - 驗收：設定狀態可見，返回時保留。

- [ ] **T24 / P1：空白、錯誤、權限與離線狀態**
  - 加入所有可恢復狀態及友善文案。
  - 驗收：拒絕定位、取消拍照、分析重試皆不阻斷核心流程。

### Milestone G — 品質與交付

- [ ] **T25 / P0：響應式與安全區測試**
  - 測試 320、390、430、768px 與桌面。
  - 驗收：無水平捲動、遮擋、底部導覽重疊。

- [ ] **T26 / P0：無障礙檢查**
  - 鍵盤、focus、標籤、點擊區、對比、reduced motion。
  - 驗收：鍵盤可走完核心流程，圖示按鈕可被讀取。

- [ ] **T27 / P0：核心流程整合測試**
  - 新使用者與日常使用兩條完整路徑。
  - 驗收：從 Welcome 到下一餐建議無死路；狀態更新正確。

- [ ] **T28 / P1：效能與視覺 QA**
  - 檢查動畫、圖片、文字溢出、點擊回饋與載入。
  - 驗收：一般手機操作流暢；無 console error。

- [ ] **T29 / P0：交付說明**
  - 建立 README，說明如何開啟、重設 Demo、哪些功能為模擬。
  - 驗收：未參與開發者可在 2 分鐘內啟動並完成測試。

## 3. 建議實作順序

```text
T01–T03 → T04–T08 → T09–T12 → T13–T18 → T19
→ T20–T24 → T25–T29
```

先完成 P0 的端到端可用版本，再加入 P1。不要先花時間完成 Trend 或動畫，卻讓餐點儲存與 Dashboard 更新尚未串起。

## 4. 測試腳本

### Scenario A：第一次使用

1. 以訪客開始。
2. 填寫基本資料，選擇「均衡飲食」、每週運動 2 天。
3. 選擇「少辣」與「便利商店」，略過定位。
4. 查看每日建議並開始記錄第一餐。
5. 完成 AI 掃描，把飯量改為半碗、醬料改為少。
6. 儲存並確認 Dashboard 數值及餐次更新。
7. 前往下一餐頁，勾選兩項採買清單。

### Scenario B：日常使用

1. 重新開啟原型，確認資料仍存在。
2. 從 Home 點中央 Scan。
3. 完成一餐並返回 Home。
4. 說出今日主要營養缺口。
5. 從 Nearby 選擇一家推薦店家。

### Scenario C：例外處理

1. 嘗試輸入不合理的身高或留白。
2. 在掃描中取消並重新嘗試。
3. 拒絕定位後查看 Nearby。
4. 使用鍵盤完成主要流程。
5. 開啟 reduced motion，確認無必要動畫停止。
